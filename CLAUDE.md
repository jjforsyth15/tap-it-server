# CLAUDE.md — tap-it-server

## What this is

FastAPI backend for TapIt (NFC-powered digital profile/card platform). SQLAlchemy models, Alembic migrations, PostgreSQL (hosted on Supabase). Deployed on Render. Talks to `tap-it-web` over REST only — no shared code between them.

See the root `tap-it/CLAUDE.md` (one directory up) for overall project context, current phase, and how I prefer to work together. This file is backend-specific.

## Layout and conventions

- `app/routes/` → `app/schemas/` (Pydantic) → `app/models/` (SQLAlchemy) → `app/services/` for logic that doesn't belong in a route. `app/core/` holds auth, dependencies, and rate limiting.
- Response model naming: `XResponse` (read model), `XCreateResponse`/`XAdjustmentResponse` (`{message, resource}` wrapper), request models are `XCreate`/`XUpdate`.
- Shared validation lives in `app/routes/validators.py` (`validate_profile_user`, `validate_card_code_in_db`, `validate_card_id_in_db`, `validate_card_data`, `validate_register_data`). Reuse these rather than re-inlining ownership/existence checks in a route.
- Migrations: `app/migrations/versions/`, run via `alembic revision --autogenerate -m "..."` then `alembic upgrade head`. Review autogenerated migrations before committing — don't blindly trust the diff.

## Auth & security

- JWT via `python-jose`, password hashing via `passlib`/bcrypt. Token creation/verification in `app/core/auth.py`.
- `app/core/dependencies.py` provides `get_current_user` (required), `get_current_user_optional` (used by e.g. anonymous beta feedback), and `require_admin` (checks `User.user_type == UserType.ADMIN`).
- Rate limiting via `slowapi`, applied per-route with `@limiter.limit(...)` (see `cards.py`, `auth.py`). Global wiring is in `main.py`.
- Be extra careful with anything touching auth, admin routes, or cross-user data access — this app has real user data and beta testers.

## Known issues (not yet fixed — ask before touching)

- `routes/cards.py`, `swap_card_profile`: the ownership check `if profile_id != current_user.user_id or new_profile.user_id != current_user.user_id` compares a *profile* ID against the current user's *user* ID in its first clause — different UUID spaces, so it will almost always be true and 403 the endpoint. Likely a copy-paste bug. Needs a fix, but confirm with Joe before changing since it may be relied on somewhere unexpected.
- `requirements.txt` is saved as UTF-16 with CRLF line endings (Windows editor artifact). Harmless for pip but worth normalizing to UTF-8 eventually.

## Current focus (Phase 2A — Administration)

- Admin dashboard endpoints are done: `/admin/dashboard/summary`, `/recent-activity`, `/action-items`, `/health` (all `require_admin`-gated). See `app/routes/admin/admin_dashboard.py` and `app/services/admin/admin_dashboard_service.py`.
- Card requests are scaffolded but not implemented: `AdminActionItemType.CARD_REQUESTS` and a `target_path` exist in the schema, but there's no `CardRequest` model, no endpoints, and the service has a literal `# Add card requests count` placeholder comment.
- No frontend admin UI exists yet in `tap-it-web` — these endpoints are unused by any client right now.

## Testing

No automated test suite (no `tests/` directory, no pytest config). `docs/TESTING.md` is the canonical manual regression checklist — keep it updated when you change user-facing behavior. If you add automated backend tests, `pytest` is the natural choice but isn't set up yet.

## Env vars of note

`SECRET_KEY`, `ALGORITHM`, `ACCESS_TOKEN_EXPIRE_MINUTES`, `CURRENT_URL`, `FRONTEND_URL`, `FRONTEND_URL_IP`, `TEAM_ID`, plus Supabase/DB connection vars. Full list in `docs/ENVIRONMENT_VARIABLES.md`. Never log secrets or tokens — there's already a logging middleware in `main.py`, don't add fields to it that could leak sensitive values.
